# Featured Art current-mandate acceptance

This contract covers only the four featured Art study destinations discovered in `art.html`. It is not acceptance of all 130 routes.

`python tools/art_study_enrichment_qa.py` preserves the established reviewed assets, sources, navigation and interaction structure. Its historical batch inventory has five supporting pictures per destination. Passing that regression does not establish the current ten-original or half-Christ mandate.

`python tools/art_study_current_mandate_qa.py --report <report.json>` is the separate strict current-mandate evidence/count check. Its exit code is zero only when the four routes pass; deficient or unverified evidence returns one. There is no reduced threshold, grandfather exemption or report-only success mode. Any full-enrichment acceptance process must invoke this command and propagate its nonzero result to an INCOMPLETE result. A green scoped correction/deployment does not satisfy this dependency.

Current observed state: all four routes have six distinct full-asset candidates in their hero/supporting slots, fewer than ten. Complete ownership/lineage and Christ-classification evidence is not yet reconciled. The strict command therefore returns one with all four routes FAIL and evidence gaps separately listed. An evidenced count of zero means no qualifying receipt has been supplied to this new schema, not that existing artwork is absent or rejected.

The registry is an observed placement inventory. It binds current page and full-image bytes. Null/unknown fields remain unverified. No classifier infers an original, ownership or Jesus Christ from a path, caption, label or filename. Responsive variants, thumbnails, full-size views and cropped or renamed derivatives never become extra originals. Byte equality detects identical files; changed-byte derivatives require the explicit lineage review. Coverage and per-original receipts must bind the exact bytes and independent Fermi/Newton evidence. The checker verifies evidence consistency; it cannot perform visual identification or authenticate a reviewer merely because their name occurs in JSON.

Qualifying original receipts must match kind, asset, SHA256, original_id, owning route, owning section and boolean depicts_christ; both reviewers must record lineage/cross-page ownership across all canonical site routes and pixel classification review. The claimed owning section must actually contain the placement. Excluded references/resources require their own hash-bound independent classification evidence; a reference additionally needs a real other-page owner section and its matching link in the picture's figure/section. Complete-page coverage receipts must match route/page SHA256 and record both reviewers' complete inventory inspection, including unmarked images, reference/resource exclusions, delivery variants and no unregistered qualifying originals. Mere generated registry entries or passing fixtures are not these reviews.

No exception has been established for these four routes. Other pages' authorized ratio exceptions, count exceptions, deferred work or unresolved scope do not transfer here. This checker does not decide those other pages.

Ordinary scoped correction/deployment continues to run the preserved regression plus strict-checker mutation tests. Test success means deficient fixtures were rejected as expected; it does not make the current content compliant. Release receipts must retain the strict command's current INCOMPLETE result and state that the deployment is scoped technical verification. Full enriched acceptance additionally requires this strict command to succeed and the relevant substantive source, artwork, native desktop/phone, interaction and owner gates. Neither this command nor CI alone confers full enriched acceptance.
